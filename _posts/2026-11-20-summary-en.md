<summary><span class="hz-item-title">PostgreSQL 19 Released with WAIT FOR LSN for Read-Your-Writes Consistency</span> <span class="hz-item-score">⭐️ 9.0/10</span></summary>

PostgreSQL 19 was released two months later than the usual September schedule, delayed mainly by a surge of AI-reported vulnerabilities. The release introduces the WAIT FOR LSN command, which allows a standby server session to wait until it has replayed the write-ahead log (WAL) up to a specified log sequence number (LSN) before executing a query, enabling read-your-writes consistency for applications that send reads to standbys. This feature simplifies a common scaling pattern where reads are offloaded to replicas, ensuring users immediately see their own writes without custom application-level workarounds. It also highlights how AI-driven vulnerability discovery is impacting open-source release cycles. The WAIT FOR LSN command accepts an optional timeout, after which an error is raised if the standby has not caught up. The LSN can be obtained via pg_current_wal_insert_lsn() on the primary and stored (e.g., in a signed cookie) for later use on the standby.

🔗 [Source](https://simonwillison.net/2026/Nov/19/postgresql-19/)

rss · Simon Willison · Nov 19, 20:43

**Background**: PostgreSQL is a widely used open-source relational database that supports streaming replication, where a primary server ships its write-ahead log (WAL) to standby servers that replay it. Because replication is asynchronous, a standby may lag behind the primary, causing reads on the standby to miss recent writes. Read-your-writes consistency ensures that a client always sees its own updates, and previously this required custom logic such as that used by Wikipedia's MediaWiki software with MySQL.
