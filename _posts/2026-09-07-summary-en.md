The discussion highlights its use of an order-0 context mixing entropy coder and a fast Burrows-Wheeler transform, with recent benchmarks showing it outperforming xz and zstd on text compression. This matters because bzip3 offers a compelling alternative for data archival and compression, potentially reducing storage costs significantly. The community debate also underscores the importance of fair benchmarking in evaluating compression tools, which affects user trust and adoption. bzip3 uses a block size of 512MB in benchmarks, while zstd's window size is left at its default (8MB), which some commenters argue is unfair. The tool includes parallel implementations of compression and decompression, and it is not yet listed on the large text compression benchmark, though it has been added to Matt Mahoney's text compression benchmark.

Burrows-Wheeler transform is a key algorithm in bzip2 that rearranges data to improve compression, and bzip3 leverages suffix arrays for speed. The tool is designed for high compression ratios, especially on text data, and supports multi-threading for better performance.
