<summary><span class="hz-item-title">Java4Shell: Critical RCE in OpenJDK's Base64 Decoder</span> <span class="hz-item-score">⭐️ 9.0/10</span></summary>

Calif.io disclosed CVE-2026-114938, dubbed "Java4Shell," a remote code execution vulnerability in OpenJDK's optimized AVX-512 Base64 decoding assembly code that allows unauthenticated attackers to trigger heap memory corruption. The flaw carries a CVSSv4.0 score of 9.2 and affects Java 17 (OpenJDK and Oracle Java SE 17.0.6 and later updates). OpenJDK is a ubiquitous runtime powering countless enterprise applications, so a remotely exploitable memory-corruption bug in a core utility like Base64 decoding puts a vast number of internet-facing services at risk. Even though reliable RCE requires environment-specific exploitation work, the potential for denial-of-service and targeted attacks is significant. The vulnerability exists only in HotSpot-based JVMs (OpenJDK, Oracle JDK, GraalVM) that generate the vulnerable AVX-512 stub; OpenJ9 and GCJ are unaffected, and Azul Prime (Zing) replaces C2 so it may not be impacted. Exploitation is sensitive to network conditions such as RTT and jitter, and heap grooming over the network is required for reliable code execution, while denial of service is more readily achievable.

🔗 [Source](https://calif.io/java4shell/)

hackernews · werrett · Nov 17, 21:11 · [Discussion](https://news.ycombinator.com/item?id=50538240)

**Background**: OpenJDK is the open-source implementation of the Java platform, and its HotSpot JVM uses hand-optimized assembly routines to accelerate common operations like Base64 encoding and decoding. AVX-512 is an x86 instruction set extension that enables wide vector processing, and bugs in such low-level optimized code can lead to out-of-bounds writes that corrupt heap memory. CVE-2026-114938 is reminiscent of previous high-profile Java deserialization flaws like Log4Shell in terms of potential impact.
