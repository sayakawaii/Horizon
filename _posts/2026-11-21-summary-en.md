<summary><span class="hz-item-title">PostgreSQL 19 Released with WAIT FOR LSN for Read-Your-Writes Consistency</span> <span class="hz-item-score">⭐️ 9.0/10</span></summary>

PostgreSQL 19 has been released, arriving about two months later than the usual September schedule, largely due to a surge of AI-reported vulnerability issues the team had to address. The headline feature is the new WAIT FOR LSN command, which lets a session on a standby server block until the standby has replayed the write-ahead log up to a specified log sequence number, enabling read-your-writes consistency for applications that send reads to replicas. This feature solves a long-standing pain point for applications that scale reads across standby servers: after writing to the primary, a user's subsequent read from a replica may return stale data. By providing a built-in, database-level primitive for read-your-writes consistency, PostgreSQL 19 removes the need for hand-rolled polling and retry logic, which will benefit backend and database engineers running read-replica architectures. The command accepts an optional timeout, for example WAIT FOR LSN '0/0306EE20' WITH (TIMEOUT '0.1s'), and returns an error if the replica does not catch up within the specified time. In practice, an application records the LSN returned by pg_current_wal_insert_lsn() after a write (for instance in a signed cookie) and then issues WAIT FOR LSN on the standby before running its read query.

🔗 [Source](https://simonwillison.net/2026/Nov/19/postgresql-19/)

rss · Simon Willison · Nov 19, 20:43

**Background**: PostgreSQL is one of the most widely used open-source relational databases, and many production deployments use streaming replication to offload read traffic to standby servers. Because replication is asynchronous, a standby can lag behind the primary by milliseconds to seconds, which breaks the common expectation that a user immediately sees their own writes. PostgreSQL's write-ahead log (WAL) records every change before it is applied, and each record has a log sequence number (LSN) that identifies its position in the WAL; WAIT FOR LSN uses these positions to synchronize a standby with a specific write. Wikipedia's MediaWiki software has long implemented a similar pattern against MySQL replication, using functions such as WAIT_FOR_EXECUTED_GTID_SET() and SOURCE_POS_WAIT().
