PWN.AI published a detailed technical walkthrough demonstrating how a malicious guest can exploit the PwnEscape Linux kernel vulnerability to cross Firecracker's microVM boundary, resolve the live VMM from inside the VM, and take control of a root-run host process. The write-up turns a Linux networking flaw into a guest-to-host code-execution primitive, but it is a practical exploitation guide rather than a new CVE disclosure. Firecracker underpins many serverless and multi-tenant container platforms, so a demonstrated guest-to-host escape raises serious questions about isolation assumptions in cloud infrastructure. The article shows that even a deliberately minimal hypervisor can be compromised when the guest kernel itself is vulnerable, pushing operators to reassess defense-in-depth beyond the VMM boundary. The exploit chain relies on the PwnEscape Linux kernel networking vulnerability (tracked as CVE-2026-99999) to read host memory from inside a guest, then uses that primitive to locate and hijack a root-run host process. Notably, the demonstrated configuration ran without Firecracker's jailer, so the production containment controls—privilege dropping, namespaces, and seccomp—were absent and would require a separate assessment if enabled.

🔗 [Source](https://pwn.ai/blog/firecracker-escape)

hackernews · SerCe · Nov 6, 19:33 · [Discussion](https://news.ycombinator.com/item?id=50397219)

**Background**: Firecracker is an open-source microVM monitor designed by AWS to run lightweight virtual machines with a minimal device model, shrinking both memory footprint and attack surface compared with general-purpose hypervisors like QEMU. Its jailer component is a companion binary that sandboxes the Firecracker process by dropping privileges and applying namespaces and seccomp filters, and it must be paired with a statically linked Firecracker binary of the same version. PwnEscape is a critical Linux kernel networking bug that lets code inside a guest VM read host memory, effectively erasing the guest-host security boundary when the guest kernel is unpatched.
