<summary><span class="hz-item-title">Python 实验性 JIT 编译器将从 CPython 中移除</span> <span class="hz-item-score">⭐️ 8.0/10</span></summary>

CPython 中的实验性即时（JIT）编译器在 Python 3.13 中引入后，经过大量开发工作，现已被移除。这一决定是在要求提交新的 Python 增强提案（PEP）以及随后的技术和程序方面的担忧之后做出的。 此次移除影响了 Python 的性能路线图，尤其是 JIT 可能抵消自由线程开销的希望，并引发了关于语言应如何追求性能优化的辩论。这也凸显了在创新与 CPython 严格的 PEP 流程之间取得平衡的挑战。 该 JIT 是一个实验性功能，需要特殊的构建标志（--enable-experimental-jit）才能启用，且默认未开启；它包含了自动引用计数操作移除和基于类型的特化等高级优化。其移除意味着用户必须依赖 Cython、Numba 或其他第三方工具等替代方案来实现类似 JIT 的性能。

🔗 [来源](https://lwn.net/SubscriberLink/1102102/0c00e4d550f25f8c/)

hackernews · f311a · 10月27日 11:17 · [社区讨论](https://news.ycombinator.com/item?id=50257419)

**背景**: JIT 编译器在运行时将 Python 字节码动态翻译成机器码以提高执行速度，与传统的解释器不同。CPython 的实验性 JIT 基于 copy-and-patch 技术构建，首次在 Python 3.13 中提供，旨在不进行重大架构改变的情况下带来性能提升。然而，由于语言的动态特性以及需要保持向后兼容性，将 JIT 集成到 CPython 中非常复杂。
